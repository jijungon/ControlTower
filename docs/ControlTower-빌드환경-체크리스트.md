# 빌드 환경 확인 체크리스트

> Control Tower 플랜의 **열린 질문 5번(빌드 환경 위치)** 확정용.
> 목적: 빌드 버전(node·java·docker)을 **SSH로** 가져올지(서버 직접 설치형) vs **GitLab API로** 가져올지(컨테이너 이미지형) 결정.
> 인프라/빌드 담당자에게 그대로 물어보면 됩니다. (2026-09-09)

---

## 1. 담당자에게 물어볼 것

### ① 빌드가 도는 위치·접속
- [ ] 코드 빌드(컴파일 + 도커 이미지 생성)는 **어느 머신에서** 도나요? 호스트명/IP와 대수?
- [ ] 그 빌드 서버는 **gw 뒤에 있나요, 직접 SSH 되나요?** 접속용 계정/키가 있나요?

### ② node·java 설치 방식 (수집 방법을 가르는 핵심)
- [ ] 빌드 서버에 node·java가 **시스템에 직접 설치**돼 있나요? (`node -v`, `java -version`으로 바로 나오는지)
- [ ] 아니면 **nvm/asdf 같은 버전 매니저**로 여러 버전을 프로젝트별로 바꿔 쓰나요?
- [ ] 아니면 빌드를 **컨테이너 안에서** 하나요? (예: `node:20` 이미지 안) → 버전이 이미지 태그에 있음

### ③ docker builder (이미지 만드는 머신)
- [ ] 도커 이미지를 만드는 머신이 **①의 빌드 서버와 같은 곳**인가요, 별도인가요?
- [ ] 빌드 도구가 **`docker build`**인가요, kaniko/buildah 같은 다른 도구인가요?

### ④ 스택 분리
- [ ] **node 빌드 서버와 java 빌드 서버가 따로**인가요, 한 서버에서 다 하나요?

## 2. 직접 볼 것 — 레포의 `.gitlab-ci.yml`

`repo` · `center` · `config` 레포의 **`.gitlab-ci.yml`** 을 열어 확인 (이 파일 하나가 "빌드가 어디서·어떻게 도는지"를 거의 다 알려줌):

1. **`image:` 줄이 있나?**
   - `image: node:20` 처럼 있으면 → **컨테이너 빌드**. 태그 = 빌드 버전 → **API로 파일만 읽으면 끝(SSH 불필요)**
   - `image:` 없이 셸에서 돌면 → 빌드 머신 직접 설치 버전 → **머신 찾아 SSH**
2. **`tags:` 줄** → 어느 GitLab Runner(=빌드 머신)가 실행하는지
3. **docker build 단계 / `services: docker:dind`** → docker builder 위치·방식 단서

**함께 볼 파일**: `Dockerfile`(`FROM node:20` 등) · `package.json`(engines) · `.nvmrc` · `pom.xml`/`build.gradle`

---

## 3. 결론 판정

| 확인 결과 | 수집 방식 |
|---|---|
| `.gitlab-ci.yml`에 `image:` 있음 (컨테이너형) | **GitLab API**로 이미지 태그·매니페스트 파싱 (SSH 불필요) |
| `image:` 없이 빌드 서버 직접 설치형 | 그 서버에 **SSH**로 `node -v`·`java -version`·`docker --version` |
| 혼재 | 레포별로 위 두 방식 혼용 |
